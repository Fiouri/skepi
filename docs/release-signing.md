# Release signing (Android)

Release APKs/AABs are signed with a dedicated SKEPI keystore that never enters the repository or CI
logs. The Expo `debug.keystore` in the generated `android/` folder is for development only.

Wiring: `apps/mobile/plugins/withReleaseSigning.js` (an Expo config plugin, because `apps/mobile/android`
is regenerated by `expo prebuild --clean`). Do not edit the generated Gradle files by hand.

## 1. Generate the keystore (once, by the maintainer)

```powershell
keytool -genkeypair -v `
  -keystore $HOME\.android-keys\skepi-release.jks `
  -storetype PKCS12 -keyalg RSA -keysize 4096 -validity 10000 `
  -alias skepi -dname "CN=SKEPI, O=Project S.K.E.P.I."
```

`keytool` prompts for the password; PKCS12 uses the same password for store and key. Use a long random
password from a password manager. Keep the file **outside** the repository (`*.jks` is also gitignored).

## 2. Gradle properties

Add to `~/.gradle/gradle.properties` (Windows: `%USERPROFILE%\.gradle\gradle.properties`), never to the
project's `gradle.properties`:

```properties
SKEPI_RELEASE_STORE_FILE=C:/Users/<you>/.android-keys/skepi-release.jks
SKEPI_RELEASE_STORE_PASSWORD=<password>
SKEPI_RELEASE_KEY_ALIAS=skepi
SKEPI_RELEASE_KEY_PASSWORD=<password>
```

In CI the same names are passed as `ORG_GRADLE_PROJECT_SKEPI_RELEASE_*` environment variables from a
GitHub Environment with required approval; the keystore is restored from a secret into a temp file.

## 3. Build behaviour

| Situation | Result |
| --- | --- |
| All four properties set, keystore file exists | Release signed with the SKEPI key |
| Any property missing or keystore file missing | `assembleRelease` / `bundleRelease` **fail** at `skepiCheckReleaseSigning` with the list of missing properties |
| `-PskepiDebugSign=true` | Signed with the Expo debug key, with a loud warning. Local E2E only; never distribute |

Debug builds and `connectedAndroidTest` are unaffected.

## 4. Backup rule

- Keep **two offline copies** of the keystore (e.g. an encrypted USB stick and an encrypted backup
  drive) plus the password in the password manager. Check the backup restores before the first public
  release.
- Losing the key means installed apps can never be updated in place; leaking it means anyone can ship a
  "SKEPI" update. Never email, upload or commit it; never paste the password into a terminal log.

## 5. Signing fingerprint (to publish with the first public release)

From the keystore:

```powershell
keytool -list -v -keystore $HOME\.android-keys\skepi-release.jks -alias skepi | Select-String 'SHA256'
```

From a built APK (what users can check):

```powershell
& "$env:ANDROID_HOME\build-tools\<version>\apksigner.bat" verify --print-certs `
  apps\mobile\android\app\build\outputs\apk\release\app-arm64-v8a-release.apk
```

The `Signer #1 certificate SHA-256 digest` line is the fingerprint. Publish it in the README, on the
website and in every GitHub release, and never the Expo debug certificate
(`Subject: C=US, O=Android, CN=Android Debug`).
