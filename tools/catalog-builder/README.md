# tools/catalog-builder

Builds and signs SKEPI's content catalog on the maintainer's machine. The app trusts a pack only when its
SHA-256 is in a catalog whose Ed25519 signature (over the exact bytes of `catalog.json`) verifies with a
pinned key (`docs/architecture.md`, `docs/threat-model.md`). Verification uses the same code as the app
(`@skepi/core` `verifyCatalog`).

**The signing key never enters the repository or CI.** Every command that reads or writes a secret key
refuses a path inside the repository.

## Files

| Path | What |
| --- | --- |
| `catalog/manifest.json` | Official packs: id, kind, version, file, titles, languages, official URL, licence, attribution, minimum tier, tags, and the publisher's checksum (Kiwix `.sha256` URL, or the Hugging Face LFS oid pinned here). |
| `catalog/test-manifest.json` | Test packs for the local HTTPS test mirror (debug builds only). `chunkSize` may be smaller than 64 MiB (power of two, from 64 KiB) so small test packs have several chunks for the P2P tests. |
| `catalog/test-manifest-newer.json` | A test pack only in the newer test catalogs (`e2e/mirror/catalogs/good`, sequence 4): the P2P catalog-propagation test. |
| `catalog/regions/*.geojson` | Region boundaries of the country packs (Natural Earth, below); `greece.geojson` (Geofabrik `greece.poly`, ODbL) is the region of the published `map-gr-20261005`. |
| `catalog/keys/release.json` | Pinned **release** public keys (active + backup). Generated by the maintainer. |
| `catalog/keys/test.json` | Pinned **test** public keys (debug builds only). |
| `catalog/embedded/release/` | `catalog.json` + `.sig` embedded in release builds (signed with the release key). |
| `catalog/embedded/debug/` | Test catalog embedded in debug builds (signed with the test key). |
| `catalog/sources/debug.json` | Catalog update source of debug builds (the local test mirror). |

## Commands

Run from the repository root (`pnpm --filter @skepi/catalog-builder exec tsx src/cli.ts <command>` or
`node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts <command>`).

```powershell
# 1. Keys (once): active and offline backup, OUTSIDE the repository. Writes <file> (secret, mode 600)
#    and <file>.pub.json (public part).
catalog keygen --key-id cat-2026a --out D:\offline\skepi\cat-2026a.key.json
catalog keygen --key-id cat-2026b --out E:\backup\skepi\cat-2026b.key.json
catalog pin --purpose release --active D:\offline\skepi\cat-2026a.key.json.pub.json `
  --backup E:\backup\skepi\cat-2026b.key.json.pub.json --out catalog\keys\release.json

# 2. Catalog: downloads each official file into the cache (resume), checks the publisher's checksum,
#    measures SHA-256 + 64 MiB chunk hashes, writes catalog.json and signs its exact bytes.
#    The sequence must always increase (default: previous + 1; previous = <out>\catalog.json).
catalog build --manifest catalog\manifest.json --key D:\offline\skepi\cat-2026a.key.json --out catalog\embedded\release

# 3. Check (also run by the release build: skepiCheckReleaseCatalog).
catalog verify --release --dir catalog\embedded\release --pinned catalog\keys\release.json

# Key rotation: a key list signed by the key it replaces (or the backup), sequence > previous list.
catalog keylist --pinned new-keys.json --key D:\offline\skepi\cat-2026a.key.json --sequence 2 --out <dir>
```

The cache defaults to `%LOCALAPPDATA%\skepi\cache` (`$XDG_CACHE_HOME/skepi/cache` or `~/.cache/skepi/cache`
elsewhere; `--cache` or `SKEPI_CACHE_DIR` override it), shared with `scripts/provision.ps1`, `e2e/run-p2p.ps1`
and `tools/rag-eval`, so already provisioned files are not downloaded again (they are still hashed and checked
against the publisher). The cache holds the project's **only copy** of the built map and places packs (their
Protomaps daily build expires), so it must never live in `%TEMP%`, which Windows Storage Sense may clean.

Until Phase 2a the cache (and the test keys) lived in `%TEMP%\skepi`. Move them once with

```powershell
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts migrate-cache
```

Every file is hashed before and after the move and the old copy is removed only when SHA-256 and size match
(a rename on the same volume, copy + rename otherwise); a different file with the same name in the target is
reported as a conflict and both are kept. The hashes are appended to `MIGRATED-SHA256SUMS.txt` in the target.
The tools print a note while files remain in the old location.

## Map and places packs (built here)

Two manifest source kinds build a pack from pinned inputs instead of downloading a finished file; the
output stays in the cache (our own copy, since the inputs expire) and is mirrored by the project:

- `pmtiles-extract` — `{ buildUrl: "https://build.protomaps.com/<YYYYMMDD>.pmtiles", region, maxzoom }`:
  the pinned go-pmtiles CLI (`scripts/content.lock.json` → `pmtilesCli`, SHA-256 checked; or `SKEPI_PMTILES`)
  extracts the region. Greece, build 20261005, z0–15: 507 MB.
- `osm-places` — `{ url: <dated Geofabrik .osm.pbf>, upstreamMd5Url, region, locale }`: downloads the extract,
  checks the publisher's MD5, runs `places/osm_extract.py` (pyosmium; `python -m pip install -r
  places/requirements.txt`, `SKEPI_PYTHON` selects the interpreter) and writes the SQLite FTS5 pack with the
  schema, classification and folded names of `@skepi/core` (`places.ts`). Rows are sorted by OSM type and id,
  so the same extract gives the same file. Greece (2026-10-04): 37,262 places, 5.3 MB.

### Signing the release catalog with the map and places packs (maintainer)

The release key never leaves the offline machine. With the cache filled (the debug catalog build of Phase 2a
already put `map-gr-20261005.pmtiles` and `places-gr-20261004.sqlite` there), run from the repository root:

```powershell
$env:SKEPI_PYTHON = "<python with pyosmium 4.3.1>"   # only if places-gr must be rebuilt
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts build `
  --manifest catalog/manifest.json --key D:\offline\skepi\cat-2026a.key.json --out catalog/embedded/release
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts verify --release `
  --dir catalog/embedded/release --pinned catalog/keys/release.json
```

The new release catalog gets sequence 2 (previous + 1). Then upload the two files of the `packs-2026-10`
mirror (`map-gr-20261005.pmtiles`, `places-gr-20261004.sqlite`) as GitHub release assets.

### Prepare here, sign offline (from sequence 3)

`build` measures the packs and signs in one step, so the signing machine needs every pack. `prepare`
measures them on any machine and writes the exact `catalog.json` bytes naming the key that will sign them
(no key read); `sign` signs those bytes as they are, on the machine with the key, and refuses another key,
a sequence that does not increase, bytes not in the canonical form, or (with `--expect-sha256`) bytes
other than the reviewed ones:

```powershell
# Any machine with the packs in the cache: catalog/pending/release/catalog.json (committed for review).
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts prepare --manifest catalog/manifest.json `
  --key-id cat-2026a --previous catalog/embedded/release/catalog.json --out catalog/pending/release
# Offline machine: sign the reviewed bytes, check, then move both files into the embedded release catalog.
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts sign --dir catalog/pending/release `
  --key D:\offline\skepi\cat-2026a.key.json --previous catalog/embedded/release/catalog.json --expect-sha256 <reviewed hash>
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts verify --release `
  --dir catalog/pending/release --pinned catalog/keys/release.json
```

Sequence 3 (2026-10-10) has the same eight packs as sequence 2 (all still the newest upstream versions,
every URL answering with the catalog's size); it exists to prove release-catalog propagation from the
desktop Station to a release phone.

## Country packs (global maps, decision 2026-10-23)

Every country has a map pack (or, when too large, map **parts**) and a places pack. Nothing is written by
hand: the regions come from Natural Earth, the manifest entries from the region index and the pinned
inputs, and CI builds one pack per job.

| Path | What |
| --- | --- |
| `regions/make_regions.py` | `regions`: one `catalog/regions/<iso2>.geojson` per country from Natural Earth v5.1.2 admin-0 (public domain; SHA-256 pinned in the script), grouped by `ISO_A2_EH`, units without an ISO code assigned by `EXTRA_UNITS` (coverage, not sovereignty), 0.05° buffer, simplified (0.005°), snapped to 1e-4°; `index.json` (name, bounding box — west > east across the antimeridian —, label point, measured sizes, parts). `units` / `plan`: map parts of large countries (below). `measured`: records dry-run sizes in `index.json`. |
| `regions/measure_regions.py` | Sizes without downloading: `pmtiles extract --dry-run` of the pinned build over region files (reads only the archive directories). |
| `catalog/regions/sources.json` | Pinned inputs: Protomaps build (date, basemap version, MD5/BLAKE3 of the planet file), Geofabrik extract date, the mirror (GitHub release) and per country the Geofabrik path and the `name:<locale>` language. |
| `catalog/regions/parts.json` | Map parts of countries over the limit: admin-1 codes, max zoom, measured size, full name. `regions` adds to each part in `index.json` its own box and the English and local names of its admin-1 units (the app's part search). |
| `catalog/countries.json` | Generated manifest (`catalog countries --pilot` or `--iso GR,CY,…`; `--parts JP:kanto` keeps only that part of a split country, for E2E test catalogs); a test keeps it equal to the generator's output. |
| `places/requirements-ci.txt` | The places tools with the SHA-256 of every wheel (CI). |
| `.github/workflows/packs.yml` | One job per pack (≤ 256 per run): build, measure, `<id>.report.json` + `<id>.ci.json`; packs are uploaded only with `upload_packs`. |

**Split rule (from the measured sizes, Protomaps build 20261022).** A country whose map is at most
1.5 GB at z15 is one pack. A larger country is split into parts of neighbouring first-level subdivisions
(Natural Earth admin-1; its regions when every region fits, e.g. Italy's 20 regions) by recursive
bisection along the longer axis, until every part measures at most 1.5 GB at z15 (dry run of the part's
own buffered polygon). A subdivision that alone exceeds 1.5 GB becomes a part at the highest zoom that
fits (z14 ≈ 48% of z15, z13 ≈ 25%). 1.5 GB leaves ~25% headroom under the 2 GB GitHub release asset
limit for OSM growth between builds; every part keeps z15 detail.

```powershell
$py = "$env:LOCALAPPDATA\skepi\venv-packs\Scripts\python.exe"   # pip install -r places/requirements.txt
$ne = "$env:LOCALAPPDATA\skepi\cache\naturalearth-v5.1.2"          # the two Natural Earth GeoJSON files (URLs in make_regions.py)
$pm = "$env:LOCALAPPDATA\skepi\cache\pmtiles-1.31.2\pmtiles.exe"
& $py -I tools/catalog-builder/regions/make_regions.py regions --ne $ne --out catalog/regions
# A country over the limit: measure its admin-1 units, plan the parts, write the part regions.
& $py -I tools/catalog-builder/regions/make_regions.py units --ne $ne --iso DE --units-out $env:TEMP\skepi\units\DE
& $py -I tools/catalog-builder/regions/measure_regions.py --pmtiles $pm --build https://build.protomaps.com/20261022.pmtiles `
  --maxzoom 15 --out $env:TEMP\skepi\units\DE-z15.json (Get-ChildItem $env:TEMP\skepi\units\DE\*.geojson).FullName
& $py -I tools/catalog-builder/regions/make_regions.py plan --ne $ne --iso DE --sizes $env:TEMP\skepi\units\DE-z15.json `
  --limit 1500000000 --pmtiles $pm --out catalog/regions
& $py -I tools/catalog-builder/regions/make_regions.py regions --ne $ne --out catalog/regions
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts countries --pilot   # or --iso GR,CY,…
```

**Inputs expire.** Protomaps keeps a daily build for about two weeks and Geofabrik a dated extract for
about a week (build 20261005 and `greece-261004` were gone by 2026-10-23). A pack can be rebuilt from
`sources.json` only while its inputs exist; afterwards the built pack (mirror + cache) is the copy. Pick a
new build and date together, regenerate `catalog/countries.json` and rebuild.

### CI build, then sign offline (maintainer)

The release key never enters CI; CI has no secret at all. Steps for a new country catalog:

1. **Build** (GitHub): Actions → Packs → Run workflow, `countries` = the ISO codes of this batch (or empty
   for every country in `catalog/countries.json`, at most 256 packs per run), `upload_packs` = on. Each
   job's `report-<id>` artifact holds `<id>.report.json` (file, size, SHA-256, chunk hashes, licence,
   attribution, inputs, tool versions) and `<id>.ci.json`; `pack-<id>` holds the pack (3 days).
2. **Fetch** on a machine with space (not the offline one):
   `gh run download <run id> --dir $env:TEMP\skepi\packs-run` — then move every `pack-*/<file>` into the
   cache (`%LOCALAPPDATA%\skepi\cache`) and every `report-*/*.json` into one folder, e.g. `C:\skepi\reports`.
3. **Prepare** (no key; measures every pack in the cache again and refuses any pack whose size, SHA-256 or
   chunk hashes differ from its CI report):
   ```powershell
   node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts prepare --manifest catalog/manifest.json `
     --manifest catalog/countries.json --key-id cat-2026a --previous catalog/embedded/release/catalog.json `
     --reports C:\skepi\reports --out catalog/pending/release
   ```
   It prints the SHA-256 of the bytes to sign. Review `catalog/pending/release/catalog.json` (schema 2,
   the country packs with `region`) and commit it.
4. **Sign offline** (the machine with `cat-2026a.key.json`, from a checkout of that commit):
   ```powershell
   node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts sign --dir catalog/pending/release `
     --key D:\offline\skepi\cat-2026a.key.json --previous catalog/embedded/release/catalog.json --expect-sha256 <hash from step 3>
   node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts verify --release --dir catalog/pending/release `
     --pinned catalog/keys/release.json
   ```
   Bring back only `catalog.json.sig`.
5. **Publish**: upload every pack file to the GitHub release named by `sources.json` → `mirror`
   (`packs-20261022`; `gh release upload packs-20261022 <files>`, ≤ 2 GB per asset, ≤ 1000 assets), check
   one download's SHA-256 against the catalog, then move `catalog.json` + `.sig` into
   `catalog/embedded/release` (next app release) and, once catalog hosting exists, to the update URL.

6. **Retire old generations** (only after step 5 is released: the new catalog is embedded in a
   published app release, or served at the update URL once one exists). Keep the newest generation and
   every generation that the embedded catalog (`catalog/embedded/release/catalog.json`) of the **last
   two app releases** references; delete every other `packs-*` release's assets. Today v0.1.2-preview
   and v0.1.1-preview both embed `packs-2026-10`, so it stays.
   ```powershell
   # The generation to delete must appear in neither of the last two releases' embedded catalogs.
   $tags = git tag --list 'v*' --sort=-creatordate | Select-Object -First 2
   foreach ($t in $tags) { git show "${t}:catalog/embedded/release/catalog.json" | Select-String -SimpleMatch 'releases/download/packs-20261022/' }   # must print nothing
   gh release view packs-20261022 --json assets --jq '.assets | length, (map(.size) | add)'
   gh release delete packs-20261022 --yes --cleanup-tag
   ```
   An app release older than the last two keeps its own embedded catalog (release builds have no update
   URL), so its downloads of a deleted generation fail; phones that hold those packs can still share
   them over P2P. Storage: at most three generations at once (newest + two embedded), ≈ 3 × 148 GB once
   every country is published.

**Assets per release.** `packs-2026-10` (Greece, embedded in v0.1.0–v0.1.2): 2 assets, 512.5 MB.
Pilot `packs-20261022`: 39 assets (31 map packs, 8 places packs), 31.96 GB, largest 1.42 GB. A full
generation of 239 countries: ≈ 550 assets (≈ 310 map packs, 239 places packs), ≈ 148 GB. GitHub: each
asset < 2 GiB, ≤ 1000 assets per release, no stated limit on a release's total size or bandwidth.

A schema 2 catalog is rejected as a whole by apps before global maps (v0.1.2-preview and older keep
their embedded catalog; their release builds have no catalog update URL and never fetch one): ship it
with the app release that reads it.

## Release builds

`apps/mobile/plugins/withContentStore.js` copies `catalog/embedded/release` and `catalog/keys/release.json`
into the release APK and adds `skepiCheckReleaseCatalog` before `preReleaseBuild`. The release build fails
when the catalog is missing, does not verify with the release keys, or the release keys equal the test keys.
Debug builds embed the test catalog and test keys instead.

## Test keys

Test secret keys live outside the repository too (`%LOCALAPPDATA%\skepi\keys`). Only their public keys
(`catalog/keys/test.json`) and the catalogs they signed are committed. To re-sign the test catalog, generate
new test keys with `keygen`, `pin --purpose test`, and rebuild `catalog/embedded/debug` and
`e2e/mirror/catalogs/*` (see `docs/phase-1c-report.md`).
