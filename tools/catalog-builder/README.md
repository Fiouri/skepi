# tools/catalog-builder

Builds and signs SKEPI's content catalog on the maintainer's machine. The app trusts a pack only when its
SHA-256 is in a catalog whose Ed25519 signature (over the exact bytes of `catalog.json`) verifies with a
pinned key (`docs/architecture.md`, `docs/threat-model.md`). Verification uses the same code as the app
(`@skepi/core` `verifyCatalog`).

**The signing key never enters the repository or CI.** Every command that reads or writes a secret key
refuses a path inside the repository.

## Files

| Path | What |
| --- | --- |
| `catalog/manifest.json` | Official packs: id, kind, version, file, titles, languages, official URL, licence, attribution, minimum tier, tags, and the publisher's checksum (Kiwix `.sha256` URL, or the Hugging Face LFS oid pinned here). |
| `catalog/test-manifest.json` | Test packs for the local HTTPS test mirror (debug builds only). `chunkSize` may be smaller than 64 MiB (power of two, from 64 KiB) so small test packs have several chunks for the P2P tests. |
| `catalog/test-manifest-newer.json` | A test pack only in the newer test catalogs (`e2e/mirror/catalogs/good`, sequence 4): the P2P catalog-propagation test. |
| `catalog/regions/*.geojson` | Region boundaries for map packs (Greece: from Geofabrik `greece.poly`, ODbL). |
| `catalog/keys/release.json` | Pinned **release** public keys (active + backup). Generated by the maintainer. |
| `catalog/keys/test.json` | Pinned **test** public keys (debug builds only). |
| `catalog/embedded/release/` | `catalog.json` + `.sig` embedded in release builds (signed with the release key). |
| `catalog/embedded/debug/` | Test catalog embedded in debug builds (signed with the test key). |
| `catalog/sources/debug.json` | Catalog update source of debug builds (the local test mirror). |

## Commands

Run from the repository root (`pnpm --filter @skepi/catalog-builder exec tsx src/cli.ts <command>` or
`node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts <command>`).

```powershell
# 1. Keys (once): active and offline backup, OUTSIDE the repository. Writes <file> (secret, mode 600)
#    and <file>.pub.json (public part).
catalog keygen --key-id cat-2026a --out D:\offline\skepi\cat-2026a.key.json
catalog keygen --key-id cat-2026b --out E:\backup\skepi\cat-2026b.key.json
catalog pin --purpose release --active D:\offline\skepi\cat-2026a.key.json.pub.json `
  --backup E:\backup\skepi\cat-2026b.key.json.pub.json --out catalog\keys\release.json

# 2. Catalog: downloads each official file into the cache (resume), checks the publisher's checksum,
#    measures SHA-256 + 64 MiB chunk hashes, writes catalog.json and signs its exact bytes.
#    The sequence must always increase (default: previous + 1; previous = <out>\catalog.json).
catalog build --manifest catalog\manifest.json --key D:\offline\skepi\cat-2026a.key.json --out catalog\embedded\release

# 3. Check (also run by the release build: skepiCheckReleaseCatalog).
catalog verify --release --dir catalog\embedded\release --pinned catalog\keys\release.json

# Key rotation: a key list signed by the key it replaces (or the backup), sequence > previous list.
catalog keylist --pinned new-keys.json --key D:\offline\skepi\cat-2026a.key.json --sequence 2 --out <dir>
```

The cache defaults to `%LOCALAPPDATA%\skepi\cache` (`$XDG_CACHE_HOME/skepi/cache` or `~/.cache/skepi/cache`
elsewhere; `--cache` or `SKEPI_CACHE_DIR` override it), shared with `scripts/provision.ps1`, `e2e/run-p2p.ps1`
and `tools/rag-eval`, so already provisioned files are not downloaded again (they are still hashed and checked
against the publisher). The cache holds the project's **only copy** of the built map and places packs (their
Protomaps daily build expires), so it must never live in `%TEMP%`, which Windows Storage Sense may clean.

Until Phase 2a the cache (and the test keys) lived in `%TEMP%\skepi`. Move them once with

```powershell
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts migrate-cache
```

Every file is hashed before and after the move and the old copy is removed only when SHA-256 and size match
(a rename on the same volume, copy + rename otherwise); a different file with the same name in the target is
reported as a conflict and both are kept. The hashes are appended to `MIGRATED-SHA256SUMS.txt` in the target.
The tools print a note while files remain in the old location.

## Map and places packs (built here)

Two manifest source kinds build a pack from pinned inputs instead of downloading a finished file; the
output stays in the cache (our own copy, since the inputs expire) and is mirrored by the project:

- `pmtiles-extract` — `{ buildUrl: "https://build.protomaps.com/<YYYYMMDD>.pmtiles", region, maxzoom }`:
  the pinned go-pmtiles CLI (`scripts/content.lock.json` → `pmtilesCli`, SHA-256 checked; or `SKEPI_PMTILES`)
  extracts the region. Greece, build 20261005, z0–15: 507 MB.
- `osm-places` — `{ url: <dated Geofabrik .osm.pbf>, upstreamMd5Url, region, locale }`: downloads the extract,
  checks the publisher's MD5, runs `places/osm_extract.py` (pyosmium; `python -m pip install -r
  places/requirements.txt`, `SKEPI_PYTHON` selects the interpreter) and writes the SQLite FTS5 pack with the
  schema, classification and folded names of `@skepi/core` (`places.ts`). Rows are sorted by OSM type and id,
  so the same extract gives the same file. Greece (2026-10-04): 37,262 places, 5.3 MB.

### Signing the release catalog with the map and places packs (maintainer)

The release key never leaves the offline machine. With the cache filled (the debug catalog build of Phase 2a
already put `map-gr-20261005.pmtiles` and `places-gr-20261004.sqlite` there), run from the repository root:

```powershell
$env:SKEPI_PYTHON = "<python with pyosmium 4.3.1>"   # only if places-gr must be rebuilt
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts build `
  --manifest catalog/manifest.json --key D:\offline\skepi\cat-2026a.key.json --out catalog/embedded/release
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts verify --release `
  --dir catalog/embedded/release --pinned catalog/keys/release.json
```

The new release catalog gets sequence 2 (previous + 1). Then upload the two files of the `packs-2026-10`
mirror (`map-gr-20261005.pmtiles`, `places-gr-20261004.sqlite`) as GitHub release assets.

### Prepare here, sign offline (from sequence 3)

`build` measures the packs and signs in one step, so the signing machine needs every pack. `prepare`
measures them on any machine and writes the exact `catalog.json` bytes naming the key that will sign them
(no key read); `sign` signs those bytes as they are, on the machine with the key, and refuses another key,
a sequence that does not increase, bytes not in the canonical form, or (with `--expect-sha256`) bytes
other than the reviewed ones:

```powershell
# Any machine with the packs in the cache: catalog/pending/release/catalog.json (committed for review).
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts prepare --manifest catalog/manifest.json `
  --key-id cat-2026a --previous catalog/embedded/release/catalog.json --out catalog/pending/release
# Offline machine: sign the reviewed bytes, check, then move both files into the embedded release catalog.
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts sign --dir catalog/pending/release `
  --key D:\offline\skepi\cat-2026a.key.json --previous catalog/embedded/release/catalog.json --expect-sha256 <reviewed hash>
node node_modules/tsx/dist/cli.mjs tools/catalog-builder/src/cli.ts verify --release `
  --dir catalog/pending/release --pinned catalog/keys/release.json
```

Sequence 3 (2026-10-10) has the same eight packs as sequence 2 (all still the newest upstream versions,
every URL answering with the catalog's size); it exists to prove release-catalog propagation from the
desktop Station to a release phone.

## Release builds

`apps/mobile/plugins/withContentStore.js` copies `catalog/embedded/release` and `catalog/keys/release.json`
into the release APK and adds `skepiCheckReleaseCatalog` before `preReleaseBuild`. The release build fails
when the catalog is missing, does not verify with the release keys, or the release keys equal the test keys.
Debug builds embed the test catalog and test keys instead.

## Test keys

Test secret keys live outside the repository too (`%LOCALAPPDATA%\skepi\keys`). Only their public keys
(`catalog/keys/test.json`) and the catalogs they signed are committed. To re-sign the test catalog, generate
new test keys with `keygen`, `pin --purpose test`, and rebuild `catalog/embedded/debug` and
`e2e/mirror/catalogs/*` (see `docs/phase-1c-report.md`).
